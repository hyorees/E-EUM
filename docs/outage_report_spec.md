# 외부 정전 정보 입력 규격 (`POST /api/outage-report`)

재난 전력복구 의사결정 지원 시스템에 **외부 시스템(예: 한전 정전 현황)** 이 정전 정보를 보내는 방법을 정리한 문서입니다.
이 형식으로 보내면 화면이 자동으로 받아서 우선순위 분석까지 진행합니다. (데모의 `POST /api/simulate` 와 같은 화면 흐름)

## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 주소 | `POST /api/outage-report` |
| 형식 | `Content-Type: application/json` |
| 필수 | 지역 식별 + `outage_ratio` + `est_hours` |
| 자동 채움 | 인구, 65~74세 인구, 병원 수, 좌표, 지역 유형 (`backend/data/regions.csv`) |
| 처리 | 형식이 하나라도 틀리면 **전체 거절(422)**, 기존 데이터는 그대로 유지 |
| 화면 반영 | 화면이 3초마다 조회하므로 보통 3초 안에 자동 갱신 |

가장 작은 요청은 이렇습니다.

```json
{ "outages": [ { "region_id": 223, "outage_ratio": 0.62, "est_hours": 18.5 } ] }
```

## 2. 요청 본문

```json
{
  "event":   { ... },        // 선택: 이번 정전 사건의 정보
  "outages": [ { ... } ]     // 필수: 정전이 발생한 시·군·구 목록 (1~1000개)
}
```

### 2-1. `outages[]` — 구역별 정전 정보

**지역 식별 (셋 중 하나, 우선순위 순)**

| 필드 | 설명 | 예 |
|---|---|---|
| `region_id` | `regions.csv` 의 `id` | `223` |
| `sido` + `sigungu` | `regions.csv` 의 시·도, 시군구 (두 값 모두 필요) | `"경상남도"`, `"창원시"` |
| `region_name` | `regions.csv` 의 `full_name` | `"경남 창원시"` |

**필수 값**

| 필드 | 형식 | 규칙 |
|---|---|---|
| `outage_ratio` | 숫자 | **0~1** 사이. 정전 42% → `0.42` (42 로 보내면 거절). 0 이면 해당 구역은 제외 |
| `est_hours` | 숫자 | 예상 복구 소요시간(시간). 0 초과 720 이하 |

**선택 값 (없으면 자동 계산)**

| 필드 | 기본값 | 보정 규칙 |
|---|---|---|
| `affected_population` | 인구 × `outage_ratio` | 인구보다 크면 인구로 보정 + 경고 |
| `vulnerable_affected` | 65~74세 인구 × `outage_ratio` | 65~74세 인구보다 크면 보정 + 경고 |
| `hospitals_affected` | 병원 수 × `outage_ratio` 반올림 (정전 50% 이상이면 최소 1) | 병원 수보다 크면 보정 + 경고 |
| `population`, `pop65`, `hospitals` | `regions.csv` 값 | 외부 값이 더 정확하면 덮어쓸 수 있음 |
| `hazard_text` | `"외부 수신 데이터"` | 화면에 표시되는 짧은 원인 문구 |
| `outage_cause` | 자동 문장 | 선로·변전소 단위 정보를 자유 문장으로 기재 가능 |

같은 지역을 두 번 보내면 거절됩니다. 숫자 자리에 문자열(`"0.4"`)이나 `true` 를 보내도 거절됩니다.

### 2-2. `event` — 사건 정보 (모두 선택)

| 필드 | 기본값 | 설명 |
|---|---|---|
| `event_id` | 현재 시각 기반 자동 | **새 정보로 갱신하려면 이전과 다른 값**이어야 화면이 새로 받습니다 |
| `type` | `"EXTERNAL"` | `TYPHOON`, `EARTHQUAKE` 등 자유 |
| `type_name` | `"외부 정전 정보"` | 화면 배너 제목 |
| `desc` | `"외부 시스템에서 수신한 정전 현황"` | 배너 설명 |
| `severity` | 없음 | 숫자. 없으면 배너에 "강도"를 표시하지 않음 |
| `occurred_at` | 현재 시각 | `"YYYY-MM-DD HH:MM:SS"` |
| `geo` | 없음 | 지도 표시용. `{"kind":"point","lat":..,"lng":..,"radius_km":..}` 또는 `{"kind":"path","points":[[lat,lng],..]}` |

## 3. 응답

**성공 (200)**

```json
{ "ok": true, "event_id": "KDN-20261029-0001", "accepted": 4, "warnings": [] }
```

`warnings` 에는 값이 보정되었거나 제외된 항목이 문장으로 들어 있습니다.

**실패 (422)** — 어떤 항목이 왜 틀렸는지 전부 알려 줍니다.

```json
{
  "detail": {
    "message": "정전 정보 형식 오류로 접수하지 않았습니다.",
    "errors": [
      "outages[0](서울 강남구): outage_ratio 는 0~1 사이 숫자여야 합니다. (받은 값: 40) 예: 정전 42% → 0.42"
    ]
  }
}
```

실패하면 **이전에 접수된 데이터는 그대로 유지**됩니다.

## 4. 호출 예시

```bash
curl -X POST http://localhost:8000/api/outage-report \
  -H "Content-Type: application/json" \
  -d @docs/sample_outage_report.json
```

접수된 내용 확인: `GET /api/outage-report` / 정전 해제: `POST /api/reset`

## 5. 현재 한계와 확장 방향

- **시·군·구 단위**입니다. 실제 정전 정보가 변전소·배전선로·개폐기 단위라면, 그 단위를 시·군·구와 인구·병원에 연결하는 **매핑 테이블**이 먼저 필요합니다. 이 매핑은 설비 정보를 가진 쪽(한전 등)의 협조가 있어야 만들 수 있습니다.
- 위 매핑이 생기면 `outage_ingest.py` 한 곳에서 변환하면 되고, 우선순위 계산·화면은 수정하지 않아도 됩니다.
- 접수는 메모리에 **현재 사건 1건만** 보관합니다(서버를 재시작하면 사라짐). 이력 저장은 향후 과제입니다.
- 인증이 없습니다. 외부 공개 환경에서는 API 키 등의 인증이 반드시 필요합니다.
- `est_hours`(예상 복구시간)를 외부에서 받을 수 없는 경우에 대비한 추정 로직은 아직 없습니다.
